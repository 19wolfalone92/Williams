# Williams Bot 4.64.39 — корневой технический аудит, 17.11.2026

**Объект:** Android `com.williamsbot.debug` + Python USDⓈ-M Futures,
`19wolfalone92/Williams`, ветка
`fix/nov17-diag21-15pairs-margin-3pct`, draft PR #251. Это **НЕ**
репозиторий Williams-AI. `main` не изменён.

## I. Воспроизведённые первопричины и исправления

1. **Пять из пятнадцати не могли открывать сделки.** Было
   `TEN_NEW_RISK_FIFTEEN_MANAGEMENT_V1`; новые SUI/NEAR/DOT/TRX/BCH
   отклонялись до оценки готовой H1-формации.
   Теперь **15 NEW-risk / 15 management** в Android и Python.
   Неизвестные контракты по-прежнему отвергаются.
2. **Fee-wallet ошибочно считался чужой маржой.** В single-asset USDT
   счёте ненулевой кошелёк BNB/другого актива ранее блокировал все
   новые входы, хотя его наличие само по себе не свидетельствует об
   активной марже. Разрешён только строго подтверждённый foreign
   fee-wallet с нулевыми PnL, initial/position/open-order/maintenance
   margin; неизвестная или меняющаяся между двумя подписанными
   сверками экспозиция всё ещё блокирует входы. Android и Python
   используют парные регрессионные данные.
3. **Спред ошибочно был источником торгового сигнала и допуска к
   отложенному ордеру.** Стандартный TC2 начальный вход выставляет
   `STOP_MARKET` с будущим `CONTRACT_PRICE`-триггером. Текущий
   bid/ask не может определить будущую цену его исполнения. Убраны
   все veto сканера и Android initial STOP placement по *текущему*
   спреду. Для `MARKET`, включая обратный немедленный вход,
   проверка актуального bid/ask оставлена. Структурный STOP,
   размер позиции, комиссии, буфер проскальзывания и signed risk
   остались обязательными. На самом фактическом срабатывании
   `STOP_MARKET` становится рыночной заявкой — цена не гарантирована.
4. **Потеря bookTicker уничтожала сигналы и вводила UI в заблуждение.**
   Python теперь фиксирует спред как UNKNOWN (-1), не отменяя H1
   анализ; Android показывает «нет данных» вместо «-100%».
5. **Нет прослеживаемого номера сборки.** Предыдущий кандидат после
   новых исправлений всё ещё назывался 4.64.38. Android
   `versionName` и нижняя граница `versionCode`, VERSION и Python
   API теперь синхронизированы на **4.64.39**; release-contract
   блокирует несовпадение. Android-публикация использует
   постоянную подпись и проверяет SHA-256 сертификата.

## II. Проверенные предохранители (статически + существующими тестами)

- Допуск только Binance USDⓈ-M Demo/Testnet и 15 одобренных
  perpetual USDT контрактов; LONG/SHORT на H1, D1/H4 контекст.
- Для нового риска разрешён TC2. NTD/Course — наблюдение
  и сопровождение уже существующих доказанных позиций.
- Перед новым Binance POST: письменное H1 доказательство,
  актуальный contract/trigger, предварительный signed account,
  exchange rules, One-Way/ISOLATED, индивидуальная маржа и
  **50% счёта** aggregate envelope, двойное чтение account
  и повторная сверка действующих позиций/STOP.
- До отправки и после возможной сетевой неопределённости:
  durable intent, уникальный client ID, запрет слепого POST-retry.
- После FILLED должна появиться проверенная биржей защитная
  `STOP_MARKET closePosition`; неизвестный статус не считается
  доказанной защитой и блокирует новый риск.
- Дневной **entry-halt при 3%** от UTC-базы учитывает торговые
  комиссии, реализованный и нереализованный PnL и не
  сбрасывается из-за пополнения. Он отменяет неисполненные
  входы, но не служит гарантией максимального фактического
  убытка при гэпах и проскальзывании. Существующий отдельный
  emergency kill при 5% не изменён.
- Существующие защищённые позиции должны продолжать STOP,
  сверку и управление, даже когда новые входы остановлены.

## III. Новые проверки

- `FuturesDeferredEntryQuotePolicyTest.kt`: отложенный STOP
  разрешается независимо от bid/ask; MARKET при неизвестном
  стакане и >0,15% спреде запрещается; LIMIT и TAKE_PROFIT
  не получают случайного разрешения.
- `tests/test_android_stale_spread_contract.py`: нет
  устаревшего spread-veto сканера, STOP и Android; немедленный
  MARKET требует topOfBook.
- `tests/test_nov17_release_apk_contract.py`: проверяет 4.64.39,
  единую версию API и APK, стабильный signer, 15 контрактов,
  3% entry-halt, наличие HALF_MARGIN и private-event guards,
  сохранённый fee+slippage риск, корректное отсутствие метаданных.

До изменения версии **CI 188c2066** был полностью зелёным:
Python/Williams Campaign, Python backend, Android APK + unit
tests и Android emulator API 35/36. Для **каждой** версии после
4.64.39 требуется точная ссылка на успешный build/run в Actions;
не выдавать прежний APK за актуальный.

## IV. Что остаётся недоказанным (нельзя заявлять «всё исправлено»)

**P0:** GitHub Actions не подтверждает реальный Demo POST, LONG/SHORT
`FILLED`→ биржевой `STOP_MARKET closePosition`, частичные исполнения,
задержки STOP, отмену при гонке и возврат после обрыва WS. Требуется
authenticated Demo-приёмка с редактированным audit ZIP, без раскрытия
ключей.

**P0:** эмулятор API 35/36 не доказывает стабильную автономную работу
на реальном Samsung/Android 17 под Doze, перезапуском, потерей сети,
нехваткой памяти и ограничениями фоновой работы.

**P1:** durable private-event inbox и intent shadow проходят кодовый
аудит, но ещё требуют независимой длительной DB fault-injection /
rollback / parity проверки перед сменой источника истины.

**P1:** полный экспертный аудит соответствия каждой из четырёх книг
Вильямса, включая рисунки, и перспективная торговая проверка не
могут быть заменены имеющимся CI. Торговая прибыльность не доказана.

**Релизная дисциплина:** не сливать PR #251 в main и не публиковать
как production/Live до физической Demo-приёмки. Подписанный
`app-debug.apk` из успешного Actions Build Android APK допустим
лишь для установки и проверки в **Binance Demo**.
