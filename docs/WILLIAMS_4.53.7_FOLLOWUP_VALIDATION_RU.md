# WILLIAMS BOT 2.1 / 4.53.7 — повторный аудит PR #133

Дата: 22 октября 2026. Исполнительная ветка:
`fix/diagnostics6-supervision-book-audit-20261021`, base main.
Этот документ фиксирует **проверенные новые изменения**, а не утверждение о полной приёмке всех книг.

## Повторная проверка

1. Проанализирована критическая процедура `NativeFuturesCampaignCoordinator`
   при закрытии позиции и очистке защитных algo: дополнительный GET
   `positionRisk` перед каждой отменой, сверка направления, типа,
   `workingType`, точной цены, количества/close-all и биржевого ID.
   Операции блокируются при появившейся позиции или чужом/неподходящем стопе.
   Остаточный межзапросный TOCTOU-риск и обменные условия проверяются
   только Futures Demo, не признаются доказанно закрытыми локальным тестом.

2. Выявлены две ошибки в NTD AO Twin Peaks (оба направления).
   Бывший код позволял пропускать не подходящий промежуточный локальный
   экстремум, выбирая более старый (делая несуществующую пару пиков).
   Кроме того, последний бар AO мог пересечь нуль, но приоритет
   `AO_TWIN_PEAKS` выдавал его за «Два пика» вместо `AO_ZERO_LINE`.
   В Python `williams_signals.py` и Android
   `WilliamsEditionRules.kt` используется непосредственно предыдущий
   подтверждённый экстремум; весь диапазон, **включая сигнальный бар**,
   остаётся на требуемой стороне нуля. Добавлены LONG/SHORT тесты:
   валидная формация, пропущенный промежуточный экстремум, пересечение
   нуля, касание нуля.

3. По пользовательскому источнику `Trading Chaos Course`,
   Level III, печатная страница 11, текст о higher-timeframe 2-Bar
   Reversal требует для LONG защитный SELL-уровень:
   **low выбранной старшей свечи + один тик**, а не минус тик.
   Для SHORT симметрично high - один тик. Исправлены оба языка:
   `williams_edition_rules.py` и `WilliamsEditionRules.kt`.
   Контрактные примеры пересчитаны: LONG 92.9 -> 93.1,
   SHORT 207.1 -> 206.9 при тике 0.1.
   Это правило относится именно к Course Air Bag, а не к
   Course Squat: последний оставлен на исходных уровнях.
   В случае одновременной H1/Course защиты на входе runtime по-прежнему
   выбирает более тесный SL, не увеличивая первичный риск.

## Не изменено

- Исполнительный профиль по умолчанию — TC2; NTD/Course не переводятся
  этим патчем в новые LIVE-кампании.
- H1 исполнительный таймфрейм, отсутствие обязательного подтверждения
  M15, правило TC2 обычного выхода через биржевой SL не изменены.
- История неизвестных завершений BNB/XRP/SOL и их net PnL не
  достраивается из предполагаемых цен стопов.

## Проверки и нерешённые ограничения

- Python lint и полный pytest CI; Kotlin JUnit/Android build/lint;
  executable/debug APK проверяются по **точному HEAD этого релиза**.
  Зелёная CI не равна биржевому приёмочному прогону.
- **Не проверено на физическом телефоне:** фактические STOP_MARKET
  POST/DELETE/trigger/fills, восстановление после потери сети,
  E2E графический экран и обновление сохраняемой базы.
- **Не сертифицировано:** полный рисунок к рисунку исходных книг,
  все альтернативные волны, отдельные NTD и Course LIVE-профили.
- Основная ветка main не изменяется: PR #133 остаётся DRAFT
  до обменной приёмки.

Не использовать появление новой версии APK как основание увеличивать
капитал или снимать биржевой защитный стоп.
