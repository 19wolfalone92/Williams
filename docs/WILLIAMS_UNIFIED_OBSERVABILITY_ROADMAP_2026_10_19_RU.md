# Williams Bot 4.31 — наблюдаемость и план развития

## Исправления, внесённые в текущем PR
1. Диагностический контракт v10: `unified_strategy_evidence` сохраняет источник TC2/NTD/Course каждого уже найденного H1-сигнала, направление LONG/SHORT, тип, роль ENTRY/ADD_ON, временную метку закрытия, триггер, защиту и структурную проверку.
2. Новая сводка по трём методикам и каждому из **10** инструментов на экране «Диагностика». Нет сигналов ≠ нет ошибок. Неполный цикл ≠ полная приёмка.
3. В ZIP появились `williams_sources.json` и `event_compaction.json`; текстовый `strategy.log` содержит краткую разбивку источников.
4. Повторяющиеся **успешные** Cockpit-сообщения о сверке Binance агрегируются с интервалом до 15 минут для одного состояния и назначения. **Не агрегируются ошибки и изменения состояния.** Биржевые события, ордера, исполнения и SQLite-сверка остаются без изменений.
5. Тесты признаков полноты сканирования, невозможности смешать/подделать источник, ценовой причинности и запрета выдавать диагностический сигнал за разрешённый ордер.

## Непременные ограничения
* Ни одно изменение диагностики не должно открыть Futures-ордер, сбросить Kill Switch, перевести Stop Loss или понизить лимит надёжности.
* Источник сигнала в ZIP не доказывает верность книжных правил. Совместная модель риска и межкнижных доливок требует отдельной верификации.
* Любой статус PASS должен указывать проверяемое свойство и конкретный корпус тестов; 100%-соответствие книгам нельзя объявить без эталонной матрицы.
* Нельзя объявлять Android автономно готовым к Futures Demo лишь по успешной CI-сборке.
