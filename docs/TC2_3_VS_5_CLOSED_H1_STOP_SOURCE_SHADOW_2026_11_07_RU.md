# TC2, 7 ноября 2026 — доказательное сравнение 3 и 5 закрытых баров H1

**Источник:** Джастин Грегори-Вильямс, Билл Вильямс, «Торговый хаос 2» (второе издание), глава 12, **PDF с. 165, печатная с. 150**. Для LONG автор описывает выход ниже минимума последних **трёх или пяти** ценовых баров; для SHORT — зеркально. Книга не предоставляет детерминированного универсального критерия, какая схема всегда лучше.

## Что сделано

Встроена в Android-систему разборов функция tc2ThreeFiveBarStudy — **наблюдательная** функция, которая отдельно измеряет обе авторские альтернативы на текущих *реально закрытых* H1 барах. Для каждой заполняются:

- точный набор из 3/5 законченных H1-баров и source-extreme по фактическим котировкам;
- исходный экстремум и защитный уровень за ним **на один биржевой тик**;
- возможность **только** затянуть существующий SL, запрет на расширение;
- достаточный разрыв между предполагаемым новым SL и актуальным MARK;
- прирост теоретической защиты в расчёте на единицу позиции;
- точное различие между доказанными свечами и отсутствием 3/5 полностью наблюдённых после обнаружения позиции баров.

При ненаступившем закрытии часа, разрыве H1, off-grid экстремуме, некорректной цене или отсутствии подтверждений возвращается структурированный отказ, не придуманная цена.

Отдельная проверка H4 не должна стирать уже полученный независимый H1-снимок: он сохраняется внутри WilliamsStopTrailReview.evidence даже если основная проверка откладывает перенос. Как и раньше, результаты попадают в журнал решений переноса, когда есть попытка либо отклонение с причиной.

## Граница полномочий и рисков

- execution_authority=false: оба наблюдательных уровня **не создают Binance-ордер**, **не закрывают позицию** и **не заменяют исходный STOP**.
- Фактическое сопровождение TC2 по-прежнему использует существующую проверенную схему, включая стоп-фрактал и предпочтение 5-барного окна, действующие H4/волатильностные veto и независимые exchange/fill/risk-ограничения.
- «Первое наблюдение позиции» не равно времени фактического исполнения. Новая проверка требует полные свечи после *наблюдения*, чтобы не заявлять недоказанную причинность.
- Это **источниковая трассировка** книжного правила, а не численная оценка того, какой вариант прибыльнее на рынке, и не гарантия отсутствия ранних выходов.
- Нельзя внедрять автоматический переход на 3-bar без слепого исторического сравнения по реальным котировкам, комиссиям и просадкам **и** без signed Demo STOP-цикла.

## Проверки

Tc2ThreeFiveBarStudyTest:
1. зеркальные LONG/SHORT с точными двумя исходными уровнями;
2. три доступных полных H1 бара при недоказанных пяти;
3. формирующаяся свеча и пропущенный час → запрет;
4. сетка биржевых тиков и опасная близость к MARK;
5. обе альтернативы в аудите, даже когда H4 недоступен и реальный перенос отложен.

Критерий завершения: JVM suite + Android APK + API35/36 lifecycle по **точному коммиту**, затем подлинные сделки Binance Futures Demo с установленным защитным STOP и непрерывным наблюдением на устройстве. Никакое программное тестирование само по себе не подтверждает биржевой STOP.

## Дополнительная проверка P0 — повторное использование уже пробитого H1 сигнала

**Источники:** TC2 PDF с.125 (WM1), с.137–139 (WM2), с.145–151 (WM3). Повторный вход по старому уровню после фактического первого пробоя не является новым подтверждённым сигналом.

В окончательной проверке перед Binance POST ранее объединялись сохранённые закрытые H1 свечи и свежие два сырых бара Binance по времени. При повторном timestamp новое сырое значение безусловно перезаписывает старое. Если сохранённый закрытый H1 бар уже достиг триггера (например high 111 при trigger 110), но «сырой» повтор этого же часа сообщил high 109, исторический факт пробоя удалялся из вычисления. Это потенциальный путь к несвоевременной повторной STOP-заявке.

Правка `williamsBookH1ObservedBreakoutBlocker`:
- проверяет целостность и почасовую непрерывность сохранённого ряда;
- перед слиянием требует совпадения **O/H/L/C по общему закрытому часу** у двух источников (объём может уточняться);
- при расхождении **ничего не отправляет** и выводит русскую причину; не выдумывает, какой источник прав;
- при согласованном подтверждённом пробое по-прежнему отклоняет повторный вход;
- проверена зеркальная LONG/SHORT регрессия `Tc2H1RawConsistencyTest`.

Это **сafety fix** допуска книги/биржи, не новый торговый сигнал и не гарантия полной точности всех свечей. В случае временного расхождения Binance на границе часа возможна безопасная задержка входа; она предпочтительнее отправки лишней заявки.
