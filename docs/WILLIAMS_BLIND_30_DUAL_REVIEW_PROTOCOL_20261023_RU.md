# Закрытие пробела между 30 слепыми графиками и независимой приёмкой — этап 2

**Данные:** 5 инструментов × 6 H1 отсечек на исходных биржевых 160 свечах, 30 графиков.
Слепой пакет уже собран из GitHub CI в `williams-blind-h1-expert-annotation-packet`. Ни один внешний человек ещё не сообщил нам свои оценки.

## Теперь реально можно принять результаты двух экспертов

Добавлена команда:

```bash
python tools/score_blind_human_wave_review.py \
  --reviewer-a /path/reviewer_a_frozen.csv \
  --reviewer-b /path/reviewer_b_frozen.csv \
  --output /path/williams_two_reviewer_wave_agreement.json
```

Два CSV обязаны иметь **строго 30** разных отсечек, каждый одну независимую личность, поля ровно как в пустом шаблоне слепого пакета. Хеш полного рыночного периода и SHA256 именно доступного на отсечке префикса вычисляются заново из закреплённых H1 баров в репозитории. Любая подмена, неизвестная дата, дублирование, неверная последовательность `known_at` фрактала, открытая справа свеча, неопределённая временная зона или несогласованная личность приводят к ошибке.

После приёма **обоих** файлов, но не ранее, запускается производственная H1-разметка. Вывод включает число согласованных меток, Cohen's kappa, конфликты, метрики покрытия прогнозами бота, отдельно `UNRESOLVED`, confusion matrix и все ошибки. При разногласиях оценивается только согласованная часть; требуется независимый арбитр для оставшихся случаев.

**Строгое ограничение:** reviewer_id и имя CSV — самодекларация, не доказательство личности, квалификации или отсутствия доступа к ответам. Даже два заполненных подложных CSV не устанавливают истинную экспертность. Поэтому `human_elliott_accuracy_certified=false` сохраняется до проверки подлинности личностей, слепоты и независимой арбитражной подписи. Unit-тесты используют именно синтетические CSV и не публикуют их как настоящие экспертные оценки.

Новые тесты: 30 реально сохранённых окон, фальшивый SHA, future leakage, одинаковые reviewer IDs, дата заморозки после оценки, конфликт всех шести срезов одной пары.
