# Binance Futures Demo / физический Android — проверяемые доказательства

Наличие зелёного APK и Python/JVM CI **не** доказывает, что при потере связи и перезагрузке Android защищённая биржевая позиция будет восстановлена.

Добавлен офлайн-валидатор `williams_demo_evidence_gate.py` + CLI `tools/validate_device_demo_evidence.py`. Он принимает экспортированные без секретов события реального телефона и проверяет цепочку:

- Установлен APK с конкретным SHA256; запущен двигатель; аккаунт Demo подтвержден подписанным снимком;
- фактический exchange fill; действующий **reduce-only** защитный стоп по полному остатку с биржевым order ID;
- остановка процесса / перезагрузка телефона; **API identity сохранён**, двигатель снова RUNNING;
- подписанный снимок позиций от биржи; защитный stop повторно подтверждён на остатке;
- при выходе существует подтверждённая причина биржи **EXCHANGE_STOP_FILL** либо действие пользователя **USER_MANUAL_EXIT**. Произвольный выход «противоположный мудрец» не считается принятым.

Все фальшивые синтетические события используются ТОЛЬКО как отрицательные/положительные unit-тесты самого валидатора. **Без реального экспорта и проверки exchange authenticity аппаратная приёмка остаётся непройденной.** Само соответствие JSON-схеме даёт статус `STRUCTURAL_PASS_REQUIRES_PHYSICAL_EXCHANGE_ATTESTATION`, но никогда `full_trade_lifecycle_certified=true`.

Проверка не передаёт API-ключи, не вызывает Binance, не открывает и не закрывает ордер. Настоящие эксперименты должны проходить только в Binance USD-M Futures Demo на телефоне и с подтверждённым защитным стопом; при неподтверждённой защите требуется существующий аварийный fail-closed механизм торгового движка.
