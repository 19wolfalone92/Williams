# Williams 4.49.0 — история, волны, выходы и фактический статус

Дата: 20.10.2026. Исходная main: `e43bdd53dff67d448117bbfdcaca26a3937328e0`, версия 4.48.0.
Работа продолжена в существующем PR #119. Его прежний HEAD: `ecc8483bfabdafb4f294339f876c4a91dfdb3fc6`.
Этот документ описывает код кандидата. Результат сборки и тестов именно конечного HEAD необходимо смотреть в проверках PR; старые зелёные проверки не переносятся на новый код.

## Прямой ответ

Бот уже сохраняет биржевую историю в SQLite и строит волновые гипотезы разных масштабов.
Однако в исходной main **не было полного последовательного прохода всех сохранённых H1-срезов**: эта работа оставалась в draft PR #119. Наличие SQLite не означало, что весь архив уже проанализирован.
В 4.49 перенесены полный причинный проход, сохранение прогресса и проверка восстановления. Фактическое завершение загрузки и прохода на телефоне требует его диагностического архива.

Разметка волн остаётся набором проверяемых гипотез и альтернатив. Временное и ценовое вложение H1 в H4/D1 само по себе не доказывает единственную правильную родословную волн.

Торговые сутки здесь начинаются в **00:00 UTC, то есть в 03:00 по Минску**.

## Найденные дефекты и внесённые изменения

1. **Дневной лимит превращался в бессрочную остановку.** Main при 3% делала `paused=true` и `auto_run=false`.
   Теперь SQLite хранит день отдельного запрета только новых входов; он истекает на следующей подтверждённой границе UTC. Операторская пауза, Kill, база риска и reconciliation остаются независимыми. Ошибка записи состояния закрывает допуск к новым входам.
2. **Будущие данные могли вытеснить прошлое.** Main ограничивала массив 1800 барами перед фильтрацией по историческому времени.
   Теперь сначала выбирается причинный префикс, затем рабочее окно; есть тест с более чем 1800 будущими свечами.
3. **Удобный локальный AO-пик мог ошибочно подтверждать степень W3.** Проверяется глобальный пик от начала предложенного цикла, его разворот и лаг 1–5 настоящих баров после ценового экстремума. Несоответствие оставляет степень неподтверждённой.
4. **Время открытия родительской свечи принималось за момент экстремума.** Ищется последний совпадающий настоящий младший high/low внутри родительской свечи. Отсутствие совпадения не заменяется догадкой.
5. **TC2 мог закрываться без SL.** В Android оставался market-close при нарушении границы коррекции; Python также закрывал по противоположному сигналу.
   Теперь оба события для TC2 — записанные наблюдения. Перенос подтверждённого стопа продолжается. Неисправность необязательного Python-анализа противоположного сигнала больше не прерывает сопровождение стопа.
6. **Полный архивный проход не был интегрирован.** Перенесены устройство/SQLite replay, модельные контрольные точки, журнал хешей и атомарная запись курсора.
   Исправление старых свечей, поздняя вставка и удаление инвалидируют старый результат; одинаковая повторная загрузка OHLCV не обнуляет прогресс.
7. **Интерфейс смешивал готовность H1 и изученность архива.** Теперь это разные формулировки, с количеством обработанных H1-срезов и числом догнанных пар. Завершение одной пары не выдаётся за завершение всех десяти.
8. **Фоновая работа и локализация.** Отдельный поток пониженного приоритета, порции до 32 событий и проверка бюджета 350 мс между событиями; при активном сопровождении/сверке проход уступает очередь. Русифицированы уведомление службы и дополнительные подписи.

Бюджет 350 мс — проверка между операциями, а не гарантия времени одной операции. Минимум свободного места для replay — 512 MiB; бюджет 512 MiB относится к сжатым полезным записям журнала, а не ко всему физическому файлу SQLite.
Минутные свечи сохраняются по потребности: принудительная многолетняя загрузка 10 полных M1-архивов на телефон не включена.

## Проверка

Для конечного HEAD требуются Android unit tests, lint, APK, Python 3.12/3.13 и release contract.
Добавлены/перенесены исполняемые проверки причинности, восстановления, глобального AO и SQL-триггеров настоящего SQLite. Новый Python regression вызывает production `_trail()` для LONG/SHORT: граница коррекции, противоположный сигнал, отказ необязательного наблюдателя; legacy NTD/Course сохраняют собственные выходы.

В этой сессии локальное окружение исполнения недоступно. Локальные команды, распаковка свежего ZIP, запуск телефона и собственный биржевой E2E не заявляются выполненными. Сборка и тесты выполняются GitHub Actions; их фактические результаты публикуются в PR #119.
Разбор диагностического архива (9) из PR #124 относится к 4.47.2 и не доказывает работу нового APK.

## Что остаётся незакрытым

- Полная загрузка всех доступных контекстных архивов и многолетний replay на конкретном телефоне, с измерениями скорости, памяти, батареи и размера БД.
- Полный визуальный эталон книг/Course, точность WM1-ангуляции и сложной рекурсивной волновой разметки.
- Исполнительная приёмка NTD/Course; до неё они остаются наблюдателями.
- Подключение новой архивной волновой модели к праву входить, доливаться или закрывать позиции — **не выполнено**. Модель сохраняет `can_place_orders=false`, `can_close_positions=false`.
- Единый полный Python/Android parity и телефонные FI-сценарии: сеть, частичное исполнение, повторный запуск, стоп-перенос и сверка.
- Контроль фактической цепочки Futures Demo: fill → биржевой SL → перенос SL → stop-fill → восстановление, отдельно в обе стороны.
- Полная русификация всех динамических сообщений и визуальная приёмка всех экранов на устройстве.
- Прибыльность после издержек и устойчивость на независимой истории не доказаны.

Процент «100% по всем книгам» по этим данным назначать нельзя. Изменения устраняют конкретные дефекты и делают недостающую архивную работу проверяемой.
