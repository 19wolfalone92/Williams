# Williams Bot 4.64.18 — диагностика V2: 25 ядер и сквозные цепочки

Дата разработки: 11.11.2026. Ветка `fix/nov10-entry-gate-flapping-4.64.18`, PR #228. Предыдущая база: Android 17, архив `Williams_Diagnostics (7).zip` с 74 существующими компонентными проверками. ZIP пользователя намеренно не публикуется в GitHub.

## Цель

Показывать не только «зелёный» статус отдельной службы, но и **какого именно доказательства не хватает в связке**: Android → REST → WebSocket → история → TC2 H1 → риск → Execution Door → ордер → FILLED → подписанная позиция → STOP → перенос/закрытие → журнал → UI → восстановление.

Компонентная PASS — это *только* результат конкретной проверки в её момент времени. Цепочка не считается выполненной на Binance Demo без единого связанного списка подписанных фактических исполнений, IDs и защитных заявок. Никакой отчёт не изменяет торговый допуск, STOP, риск, ключи и действия пользователя.

## 25 независимых компонентных ядер

1. ANDROID_PROCESS: FGS, автозапуск, прошлые OOM, реальные причины завершения.
2. HEAP_PRESSURE: текущий Java heap, headroom, native allocation, предупреждение об OOM.
3. FOREGROUND_WORKER: один активный worker, heartbeat, восстановление, FSM.
4. SQLITE_JOURNAL: quick_check, состояние, восстановление историй/закрытий.
5. EXCHANGE_CLOCK: время Binance и возраст подписанного доказательства.
6. PUBLIC_REST: 15 утверждённых пар и свежесть публичных котировок.
7. PUBLIC_STREAMS: market/bookTicker/depth WebSocket.
8. SIGNED_ACCOUNT: приватный REST, завершённая сверка позиций и ордеров.
9. NETWORK_GOVERNOR: Binance request weight, 429/418, bounded cooldown.
10. PRIVATE_STREAM: живой listenKey WS, события, signed REST после события.
11. H1_HISTORY: 1h/4h закрытые свечи и сохранённая история.
12. WAVE_RESEARCH: 1d/4h/1h/15m/архив с запретом look-ahead.
13. SCANNER: progress, время, покрытие утверждённых контрактов.
14. EXECUTOR_BACKLOG: очереди Scanner, истории, индикаторов и TC2 Research.
15. TC2_RULES: Alligator/AO/AC/фракталы, WM1/2/3, происхождение сигналов.
16. RISK_GATE: equity, суточная просадка, портфельный риск, ликвидация.
17. EXECUTION_DOOR: синхронизация, TTL подписи, durable lease, safe rejection.
18. PENDING_ORDERS: pending stop-entry, client IDs, частичное исполнение.
19. POSITIONS: действительные позиции, владение, signed state.
20. STOP_PROTECTION: биржевой активный STOP, сопоставление qty/side/client ID, задержка после FILLED.
21. STOP_TRAILING: перенос STOP, подтверждение биржей, исторический журнал.
22. EXITS_PNL: закрытие, расчёт комиссий/funding и PnL.
23. RECONNECT_RECOVERY: восстановление после Wi-Fi/перезагрузки и safe monitoring.
24. UI_CONSISTENCY: экран vs независимый STOP/account и журнал.
25. FORENSIC_EXPORT: полнота диагностического архива и сравнение снимков.

Для каждого ядра отчёт перечисляет: собственные исходные тесты с вердиктами, отсутствующие тесты, непосредственные зависимости, минимальные скалярные телеметрические данные и доказательство, требуемое для реальной приёмки. **FAIL**, **WARNING**, **NOT_VERIFIED** и **PASS** остаются разными статусами. Не найденная проверка НЕ превращается в PASS. Все межъядерные рёбра имеют `end_to_end_exchange_verified=false` без независимых подписанных фактических receipts.

**Независимые перепроверки:** попытка показать разрешённые новые входы при подписи старше 90 секунд; готовность координатора при `RECONCILE_REQUIRED`; неоднородный по времени снимок; реальная позиция без PASS по STOP; дублирующиеся и ещё не сопоставленные тесты.

## Тайминг FILLED → защитный STOP

`WilliamsFillStopTimingForensics` сортирует 150 последних событий Android **по времени** (записи раньше выгружались от новых к старым), находит `ORDER_TRADE_UPDATE / FILLED`, после которого фиксируются `ALGO_UPDATE NEW` и отдельный `COCKPIT_EXECUTION OPEN_PROTECTED / PASS`. Порог предупреждения: более **5 секунд** до наблюдения `OPEN_PROTECTED`. События старше 24 часов не интерпретируются как актуальные. Второй FILLED по тому же символу до связанной защиты → **AMBIGUOUS**, а не ложная корреляция.

Архив #7 дал BCHUSDT: FILLED в 02:13:35.726Z, первое ALGO NEW через 11.166 с, первое OPEN_PROTECTED через 13.153 с. Это **задержка подтверждения по логам Android**, НЕ доказательство биржевого времени создания защитного STOP и НЕ доказательство, что позиция была в рынке без STOP ровно столько же. Корреляция по символу/порядку не заменяет привязку clientOrderId ↔ clientAlgoId и подписанную историю Binance. P0 по времени реальной защиты по-прежнему отдельно: issue #229.

Никогда не размещать дубль STOP, не отменять существующий ордер и не снимать fail-closed блокировку из этой статистики.

## Ресурсы и OOM

`WilliamsDiagnosticResourceHealth` измеряет 3 независимых контура: текущая память JVM, лимит Binance REST weight/cooldown и размеры очередей scanner/research/history/indicator. Превышение 80% heap/малый headroom, 90% REST weight, 429/418, активный cooldown либо аномальная длина очередей → WARNING, отсутствующие счётчики → NOT_VERIFIED. Историческая запись `OutOfMemoryError` никогда не исчезает из AND-04 просто потому, что текущая память свободна.

Формирование ZIP остаётся потоковым. Внутренний «preview» гипотетических observer-событий ограничен 50 рядами/источник, а **полный** журнал выгружается через NDJSON и проверяется по фактическому числу строк.

## Проверка целостности ZIP

Новый ZIP сначала пишется во временный файл, затем **повторно читается**: CRC32 и размер каждого entry пересчитываются потоковым буфером 8192 байт, проверяется наличие полного набора ключевых исходных доказательств, корректный timestamp и точное число строк `observer_paper_full_history.ndjson` против metadata. Только после успешной проверки выполняется атомарное замещение предыдущего архива. При ошибке старый ZIP остаётся на диске, UI не объявляет текущий отчёт сохранённым.

## Экспорт и экран

Новые файлы:
- `diagnostic_chain_audit.json`: 25 ядер, все зависимости, недостающие тесты, критические межъядерные противоречия.
- `diagnostic_chain_comparison.json`: наблюдаемые ухудшения/улучшения ядер относительно последнего **полного** ZIP. Улучшение не означает доказанное исправление.
- `futures_fill_stop_timing.json`: ретроспективный наблюдательный тайминг, с пропусками/неоднозначностью.
- `runtime_resource_diagnostics.json`: heap, Binance weight, многопоточные очереди.

Android-экран показывает блоки «FILLED → STOP», «Память, REST лимиты и очереди», «Ядра и связи», развёртываемый список всех 25 ядер, независимые прежние компонентные проверки, сравнение, экспорт. Compose **не копирует** гигантские сырые исследования и весь биржевой журнал: только лёгкие JSON-деревья. Детальные исходные данные остаются в валидированном ZIP.

## Тесты

- `WilliamsDiagnosticChainAuditTest.kt`: известные/новые проверки, пустой снимок, дубликаты, небезопасный signed gate, активный STOP, privacy, сравнение.
- `WilliamsFillStopTimingForensicsTest.kt`: порядок событий, 11.166/13.153 с, двойной FILLED, отсутствующее подтверждение, маскировка пользовательских строк.

- `DiagnosticsArchiveIntegrityTest.kt`: ZIP с обязательными данными, отсутствующий signed STOP, ошибка архива NDJSON, неверный timestamp.
- `test_android_46418_all_core_diagnostics_contract.py`: жёсткая проверка связи UI, генератора отчёта, ZIP, чистых метрик и неизменности Execution Gate.
