# Williams 4.50.1 — паспорт заявки H1 и достоверность диагностики

Исходная main: a92b1e9824ac6a7da2f915af18ed7a3254a3ca44, версия 4.49.0.
Продолжение незавершённого PR #103. Старую реализацию H1/M15 заменяет паспорт H1 с привязкой к конкретной попытке отправки и фактическому журналу исполнения.

## Выполнено

- Паспорт содержит исходный signal ID, книгу-владельца, направление, сигнал Мудреца, H1-время, уровни входа/начального SL, количество, риск, leverage и контекст доказательства.
- Отдельный attempt ID различает повторные вызовы с тем же клиентским ID. Порядок append-only записей определяется SQLite ID, а не ненадёжным сравнением равных/откаченных часов.
- Production NativeEngine связывает координатор с журналом. PREPARED должен быть сохранён до любых изменений, связанных с новой заявкой. При отказе записи новый ордер не отправляется; флаг остановки всего движка не устанавливается.
- COORDINATOR_RETURNED и EXECUTION_EXCEPTION_UNVERIFIED фиксируют результат. Исключение не выдаётся за доказанный отказ Binance. Потеря записи результата после принятой заявки не инициирует повторный ордер.
- Для чтения восстанавливается наиболее новая запись, даже если кэш decision_execution не обновился. Поздняя сверка соответствующего exchange-intent может подтвердить результат ранее неизвестной попытки.
- Данные ордера сопоставляются по symbol, client ID, направлению, источнику и signal ID. Старый контракт не предполагал обязательного symbol и мог приписать неполные сведения не той записи.
- Исправлено поле стопа: production использует protection_client_id, а старый экспорт искал protective_client_id. В цепочке теперь сохраняются также время сверки, идентификатор биржевого ордера, исполненный объём и фактическая цена.
- Passport ищет нужную запись во всём журнале, поэтому ограничение визуального списка последними 12 строками не прячет более ранний вход. Доливка отдельно связывается с родительской кампанией; её стоп не выдаётся за независимый стоп доливки.
- Защита не помечается свежей при устаревшем/будущем времени, неподтверждённых часах, закрытой кампании, несовпадении владельца или неразрешённом прежнем stop ID.
- На графике выбранной пары появился отдельный русский паспорт: план, результат, ордер и защита разделены. Риск показывается в процентах, незаписанные значения не заменяются нулём.
- Расширены русские пояснения сканера, блокировок H1, Мудрецов, направлений и статусов кампаний. Исходные коды сохраняются в технических деталях и JSON; неизвестные значения не угадываются.
- Исправлена дедупликация наблюдений: после ошибки записи состояние не заносится в кэш как успешно сохранённое. Сбой записи события наблюдения больше не скрывается возвратом SQLite -1.
- В 4.50.1 строгая вставка ограничена событиями наблюдений кампании: у User Stream сохранён прежний best-effort контракт raw-вставки. Это устраняет внесённый в 4.50 риск нового необработанного исключения SQLite при возврате -1, не меняя обработку ордеров/сделок. Общая устойчивость User Stream при полном отказе БД не объявляется доказанной.

## Хранение, производительность и совместимость

TradingAuditStore использует схему 5 с новой таблицей h1_entry_passport_events. Добавление сохраняет прежние orders/trades и экспериментальную таблицу entry_passport_events из прежнего PR103. UPDATE/DELETE новой таблицы запрещены SQL-триггерами. Это журнал попыток, а не основной источник финансовых состояний: исполнение по-прежнему принадлежит FuturesExecutionStore и координатору.

Обычный UI получает последние события всех пар одним индексированным SQL-запросом. Полная диагностика дополнительно выгружает до 500 последних паспортных событий на пару. Архивная волновая модель и алгоритмы входов/выходов не переписывались.

Паспорт не выполняет REST-запросов и не добавляет M15-подтверждение. Он не выдаёт торговое разрешение и не меняет риск-лимиты. TC2 остаётся владельцем новых рисков, NTD/Course — наблюдателями. Остаются 10 Futures Demo контрактов, LONG/SHORT и выбранная SL-политика TC2.

## Проверки

- Kotlin: конкретный стоп/ордер; чужой symbol, side, source, signal; дубли идентичности; запись старше последних 12 строк; доливки и родитель; устаревшая/будущая сверка; неизвестный исход и позднее подтверждение.
- Production NativeFuturesCampaignCoordinator с реальным подписывающим адаптером и моделируемой биржей: PREPARED до первого изменения, LONG/SHORT, невозможность отправки без аудита, отсутствие повторного финансового эффекта после ошибки записи результата.
- Настоящий SQLite выполняет SQL из production-кода: аддитивное обновление схемы, перезапуск, откат незавершённого результата, неизменность событий и выбор последнего события при откате часов.
- Русские сообщения: известные блокировки H1, режим наблюдения, состояния сканера и названия Мудрецов.
- Exact-HEAD GitHub CI: Python, release contract, Android unit tests, lint и APK. Актуальные результаты и SHA приведены в связанных PR выпуска.

## Границы результата

Локальная командная среда в этой сессии недоступна; проверки выполняются GitHub Actions. Телефон, фактические Demo fills/stop-fills и многодневная автономность не проверены.
Полная русификация всех возможных произвольных ответов Binance, полный визуальный аудит Course, рекурсивная правильность волн и исполнительная приёмка NTD/Course остаются открытыми.

Паспорт не подтверждает прибыльность или готовность всех рыночных сценариев. Статус защиты — наблюдение последней сверки, а не новое разрешение на ордер.
