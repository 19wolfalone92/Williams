## Найденное в источниках

1. **Аллигатор:** median `(H+L)/2`, SMA seed из ровно N значений, затем
   рекурсия `(previous*(N-1)+median)/N`, пары13/8,8/5,5/3. Все линии
   рассчитываются из одного графика. Аналогия младших TF в книге — не замена
   реальных H4/D1 данных и не инструкция загружать три других графика.
2. **Ошибка данных:** Python `mean()` пропускал NaN в начальном окне.
   `[100,100,NaN,100,100]` давал seed100; теперь UNKNOWN, как в Android.
   Это инженерное правило для отсутствующих данных, а не новый сигнал Вильямса.
   На полных конечных данных рекурсия и смещения сохранены.
  Отдельно проверены nullable `Float64`/`Int64`: `pd.NA` тоже остаётся UNKNOWN,
  хотя pandas пропускает его при `mean()` и `all()` по умолчанию.
3. **Хвост Аллигатора:** уже вычисленные значения могут быть нарисованы правее
   последней цены; общие известные точки всех трёх линий есть только на3 шага.
   Нельзя подставлять будущие OHLC или экстраполировать отсутствующие Lips.
4. **Распределение:** EN184–185 и оба перевода подтверждают прибыльность первой
   позиции до наращивания и пример количества1,5,4,3,2. Это не проценты риска.
5. **Частичный выход:** EN186 явно оставляет решение о полном/частичном выходе
   трейдеру. Обязательный50% trim из этого примера не реализовывался.
6. **Ошибка переводов:** EN203 / print174 содержит один пункт `Extreme Squat`.
   RU224 PDF182 / print167 и RU314 PDF243 печатают отдельные «крайний» и
   «спящий». Все три изображения просмотрены: это не только ошибка OCR.
   Новый «спящий стоп» из перевода не вводился.
7. **Психология не пропущена:** EN188–204 содержит поддержку, утренние3 страницы,
   предлагаемые6 недель практики,8 недель до перечитывания, еженедельное
   уединение и checklist мотивов/ошибок. Это человеческая практика; реестр не
   приписывает боту эмоции, автоматическое разрешение риска или доказанную доходность.

## Безопасность изменения допуска

Новые входы, добавления и открытие обратной позиции разрешены только для
BTC/ETH/BNB/SOL/XRP/DOGE/ADA/LINK/AVAX/LTC USDT. Scan, данные,
reconciliation, STOP, trail, выход и отмена по проверенной идентичности
остаются доступны и для SUI/NEAR/DOT/TRX/BCH.

| Старое состояние | Обязательное поведение |
|---|---|
| Unfilled | Сохранять client id, pending liability и резерв; не открывать ещё один intent |
| Partial | Сверить фактический fill и остаток; существующая логика отменяет остаток с readback, защищает исполненный объём |
| Triggering | Дождаться/запросить actual child; parent не считать исполненной позицией |
| Unknown | Не считать отсутствующим, не повторять POST, не освобождать резерв; после signed read восстановить ту же цепочку |
| Filled | Подтвердить owned STOP и продолжать исходный lifecycle; запретить новые добавления по management-only символу |

Смена допуска не является приказом отменить все старые заявки. Уже размещённая
pending-заявка может исполниться после обновления; этот риск остаётся в ledger.
Политика явно экспортируется в execution snapshot как
`TEN_NEW_RISK_FIFTEEN_MANAGEMENT_V1`. Максимум кампаний10, daily3%, UTC reset
и API/подпись аккаунта не расширялись.
