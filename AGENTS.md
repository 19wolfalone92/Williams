# AGENTS.md — обязательный порядок работы с Williams Bot 2.1

Этот файл обязателен для AI-агентов и автоматизированных помощников, изменяющих код в репозитории `19wolfalone92/Williams`. Требования пользователя имеют приоритет. При неопределённости остановить изменения и сообщить об ограничении.

## 1. Изоляция проектов
- Этот репозиторий — **только Williams Bot 2.1**. Не создавать и не менять здесь Williams AI ради задач Williams AI.
- `19wolfalone92/Williams-AI` — отдельный проект. Никаких автоматических синхронизаций, копирования веток, коммитов или смешанных PR между проектами.
- Не изменять другую кодовую базу в рамках задачи по этому репозиторию без отдельной явной команды пользователя.

## 2. Один активный автор изменений
- **Не более одной активной сессии/чата/агента, записывающего код в этот репозиторий, в каждый момент времени.**
- Перед записью установить, что текущая сессия назначена единственной активной пользователем или действующим координатором. Если другая сессия потенциально редактирует те же файлы или владение неясно — остановить запись и уточнить владение, не «перехватывать» работу.
- Наличие нескольких старых draft PR само по себе не означает несколько активных авторов; отсутствие активных GitHub Actions не доказывает исключительное владение.
- Автоматические сборки и тесты GitHub Actions не считаются автором, но их результаты необходимо учитывать перед слиянием.
- Этот документ является правилом координации, **не технической блокировкой** чужих чатов/запросов.

## 3. Обязательная проверка перед каждым изменением
1. Прочитать актуальные `main` SHA и изменяемую ветку/коммит.
2. Просмотреть открытые PR и пересекающиеся изменения, отдельно — незавершённые CI/workflow runs.
3. Определить один текущий интеграционный поток работы; не создавать параллельные дубли уже внесённых правок.
4. Перед записью повторно удостовериться, что HEAD целевой ветки не изменился неожиданно.
5. При конфликте, расхождении SHA, непонятном владельце ветки или пересечении файлов: **остановить запись**, описать конфликт и не перезаписывать содержимое.

## 4. Ветки, тестирование и слияние
- Не коммитить изменения в `main` напрямую. Создать отдельную ветку от актуального `main` либо осознанно продолжить единственную согласованную рабочую ветку.
- Не применять force-push, `reset --hard`, массовые cherry-pick или слепое объединение старых веток; не заменять работу другого автора.
- Для каждой правки открывать/обновлять PR с целью, перечнем файлов, базовым SHA, тестами, оставшимися рисками.
- Проверить изменённые файлы, логику и применимые автоматические тесты. Не утверждать «проверено», если сборка/тест не выполнялись.
- При красном CI, конфликте или неразрешённом дефекте **не сливать** PR.
- Сливать **по одному PR** после проверки совместимости с текущим `main`. После каждого слияния повторно читать `main` и актуализировать следующую ветку; не объединять пачку PR без отдельной оценки.

## 5. Особые требования торговой безопасности
- Любые операции с реальными средствами, размещение ордеров или переход в live-режим запрещены без отдельного явного разрешения пользователя и подтверждённых защитных проверок.
- Сохранять и проверять fail-closed поведение при отсутствии подтверждённого защитного STOP/SL, корректность восстановления после перезапуска и неизменность идентичности аккаунта.
- Не подменять тесты обещаниями «100% по книгам»: соответствие первоисточникам и реальные торговые результаты требуют независимых проверок.
- Не сохранять в репозитории секреты, ключи API, токены, пароли и приватные данные.

## 6. Отчёт по каждой сессии
В завершение сообщать: репозиторий, ветку, commit SHA/PR, какие тесты действительно завершились, что осталось, что НЕ проверено и трогался ли `main`. Если работу остановили — не продолжать запись без новой команды пользователя.
