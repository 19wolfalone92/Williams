# Williams Bot 4.10.0 — инструкция для владельца

Если вы мало знакомы с программированием, начинайте отсюда.

## 1. Что это

Это проект торгового бота Williams + Android Dashboard.

По умолчанию он настроен на **Binance Spot Testnet**, то есть для безопасного тестирования без использования реальных денег.

## 2. Что нужно сохранить

Сохраните весь ZIP-архив целиком. Не удаляйте отдельные файлы из проекта.

## 3. Что НЕ нужно делать

- Не вставляйте API key/secret в GitHub.
- Не отправляйте кому-либо ваш Binance API secret.
- Не включайте LIVE, пока Testnet не проверен длительное время.
- Не удаляйте SQLite-файлы во время работы бота.
- Не меняйте параметры риска наугад.

## 4. Первый запуск

На компьютере:

1. Установить Python 3.11+.
2. Распаковать архив.
3. Скопировать `.env.example` в `.env`.
4. Придумать длинный `MOBILE_API_TOKEN`.
5. Установить зависимости:

```bash
pip install -r requirements.txt
```

6. Проверить recovery:

```bash
python recovery_test.py
```

Ожидаемый результат:

```text
Recovery tests: 10/10 passed
```

7. Запустить backend:

```bash
python run_server.py
```

## 5. Binance Testnet

Создайте отдельные Testnet API key/secret и в Android-приложении введите их в Settings.

Используйте только ключи без разрешения на вывод средств.

## 6. Android

Открыть проект в Android Studio и собрать приложение `app`.

В приложении:

- Backend URL — адрес компьютера/сервера с backend;
- Mobile API token — значение из `.env`;
- Binance API Key — Testnet key;
- Binance API Secret — Testnet secret;
- Binance Testnet — включён.

После подключения сначала используйте `RECOVER`, затем `START`.

## 7. Если видите RECONCILE_REQUIRED

**Не запускайте торговлю повторно.**

Это означает, что бот специально остановил новые входы, потому что локальное состояние и состояние Binance не совпали.

Сначала нажмите `RECOVER` и проверьте логи. Если расхождение не исчезает — остановите бота и разберитесь с балансом/ордером.

## 8. Когда можно переходить к LIVE

Только после длительного Testnet-теста, включая:

- перезапуск backend;
- отключение сети;
- закрытие приложения;
- повторное подключение WebSocket;
- TP;
- SL;
- восстановление после crash;
- отсутствие OCO;
- проверку дневных лимитов.

Даже после этого автоматическая торговля остаётся финансово рискованной.

## Новый рекомендуемый вариант: VPS 24/7

Компьютер дома больше не нужен для постоянной работы бота. Папка `deploy/` содержит Docker + Caddy-конфигурацию для VPS. Caddy даёт HTTPS/WSS, backend автоматически перезапускается, состояние SQLite и зашифрованные Binance-ключи сохраняются на VPS.

Запуск на VPS:

```bash
cd deploy
./install_vps.sh
```

Нужны VPS с публичным IP и домен, указывающий на VPS. После установки в приложении указываются HTTPS-адрес backend и Mobile API token. Binance API Key/Secret вводятся один раз; на телефоне они больше не сохраняются.
