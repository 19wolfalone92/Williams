# Автоматическая сборка APK через GitHub Actions

Проект настроен так, чтобы после загрузки в GitHub **не нужно было вручную запускать сборку**.

## Что происходит автоматически

После каждого `push` в ветку `main` (или `master`), если изменились Android-файлы:

1. GitHub запускает Actions.
2. Устанавливаются JDK 17, Gradle 8.9 и Android SDK 35.
3. Проект собирается.
4. Создаётся **устанавливаемый debug APK** — `app-debug.apk`.
5. Дополнительно проверяется release-сборка — `app-release-unsigned.apk`.
6. Для APK создаются SHA-256 контрольные суммы.
7. Файлы автоматически публикуются как **Artifacts**.

## Где взять APK

В GitHub:

**Actions → Build Android APK → последний успешный запуск → Artifacts**

Там будет архив:

- `williams-bot-debug-apk-...` — это APK, который можно установить на телефон.
- `williams-bot-release-unsigned-...` — проверочная release-сборка без постоянной подписи.

Для обычного использования бери **debug APK**.

## Нужно ли что-то настраивать в GitHub Secrets?

**Нет, для автоматической debug-сборки — не нужно.**

Binance API-ключи, VPS-токены и другие секреты в APK не зашиваются и в GitHub не передаются.

## Важно про release APK

Release APK сейчас собирается без постоянного signing key, если в репозитории нет `keystore.properties`.

Это сделано специально: секретный ключ подписи нельзя хранить в открытом GitHub-репозитории.

Когда понадобится полноценный постоянный release APK для обновлений через установку поверх предыдущей версии, можно один раз добавить GitHub Secrets для signing key. После этого GitHub Actions сможет подписывать release автоматически.

## Если сборка упала

Открой:

**GitHub → Actions → Build Android APK → красный запуск → шаг, на котором появилась ошибка.**

Логи этого запуска позволяют определить проблему. Повторно запускать сборку вручную обычно не требуется: после исправления и нового `push` она запустится сама.
